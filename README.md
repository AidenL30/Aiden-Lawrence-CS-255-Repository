Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design? The Driverpass project was a project that required me to model and document requirements. This project involved designing an application that trains future drivers for upcoming tests and exams. The client that requested this application to be completed required that the lessons that are being offered are provided in 3 distinct packages for purchase through the application. The client had also requested that the system should have properly documented UML models for use cases in the system, as well as other model diagrams that represented the system as a whole. 

What did you do particularly well? Overall I felt that I was able to collect the requirements for each use case efficiently and without too much nuance. However I feel as though how I translated these requirements could have been addressed in a cleaner manner. I also feel as though that my evaluations for the various object models and use case diagrams were efficient and easy to understand. However, I recognize that this simplistic manner may not have been the best approach when required to build a sophisticated model system. 

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it? I would choose to revise the UML use case diagram as a whole. Overall, my Use case diagram was not created with the proper annotation, which can cause problems if this were an official commercial ready software product. I would choose to organize my use cases more efficiently and make an attempt to group these cases with the actors that they are assigned with. I would also choose to add a diagram legend, this would allow viewers who are unfamiliar with UML diagrams to gain a foundational understanding of how the system works. 

How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing? When interpreting user needs, it is always important to implement any user feedback into the project as best as possible. Users have a different perspective on software systems compared to a development team. Users regularly interact with the primary functions of any system and can spot and identify many issues with these interactions. Users also are more likely to return to or continue using a software system if they notice that their needs are being met and accounted for. This builds trust with consumers and helps developers understand their consumer base on a much deeper level. 

How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system? When designing software, there are many practices that I like to employ to keep the workflow smooth One of these practices is breaking down work into different sections that way I do not become overwhelmed with the workload. Another tactic that helps me develop programs is building tree models on my whiteboard for which objects interact with each other and which objects inherit data from which. Creating a tree model allows me to keep my thoughts organized, as well as have a foundation for what needs to be created/implemented in future iterations.
